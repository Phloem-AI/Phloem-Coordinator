Connecting Remote MCP in OpenCode

OpenCode supports remote MCP servers and makes their tools available alongside its built-in tools. This guide adds a Streamable HTTP server to a project-level opencode.json file.

1. Gather your server details

Get the remote MCP URL, for example https://example.com/mcp, and confirm whether the server uses API-key headers or OAuth authentication.

2. Open your OpenCode configuration

Create or open opencode.json in the project root. OpenCode also supports a global configuration at ~/.config/opencode/opencode.json. Project configuration overrides conflicting global values.

3. Add the remote server

Add a unique name under the top-level mcp object. Use an environment variable for the token:

{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "my-server": {
      "type": "remote",
      "url": "https://example.com/mcp",
      "enabled": true,
      "oauth": false,
      "headers": {
        "Authorization": "Bearer {env:MY_MCP_TOKEN}"
      }
    }
  }
}

Set MY_MCP_TOKEN in the environment used to launch OpenCode. Do not put a real credential in a project file committed to source control.

4. Authenticate when required

For OAuth-enabled servers, remove the static bearer header and omit oauth: false. OpenCode can discover OAuth automatically, or you can run:

opencode mcp auth my-server

For a server with pre-registered OAuth credentials, configure its oauth object and reference client values through environment variables.

5. Verify and use the tools

Start OpenCode in the project and list the configured servers:

opencode mcp list

Once connected, ask OpenCode to use the server by name, such as Use the my-server tools to inspect the current project status. Run opencode mcp debug my-server if the connection or OAuth flow fails.

Tip: OpenCode registers MCP tools with the server name as a prefix. Keep the server name short and clear, and disable unused servers or tools to avoid adding unnecessary context to every session.
