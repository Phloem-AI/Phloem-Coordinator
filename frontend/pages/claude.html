Connecting Remote MCP in Claude Code / Claude Desktop

Claude Code and Claude Desktop can connect to any remote MCP server over HTTP (Streamable HTTP) or SSE. This guide shows how to add a remote server, authenticate it, and verify the connection.

1. Gather your server details

Collect the MCP endpoint URL from your server provider. Most remote servers expose a single endpoint, for example https://example.com/mcp. Also note whether the server requires a bearer token, API key, or OAuth sign-in.

2. Add the server with the CLI

From your terminal, register the server with Claude Code:

# HTTP (Streamable HTTP) — recommended
claude mcp add --transport http my-server https://example.com/mcp

# With a bearer token
claude mcp add --transport http my-server https://example.com/mcp \
  --header "Authorization: Bearer YOUR_TOKEN"

# SSE (deprecated transport)
claude mcp add --transport sse my-server https://example.com/sse

Claude Code writes the configuration to ~/.claude.json (local scope) or .mcp.json (project scope). Use --scope user to make it available across all projects.

3. Authenticate (if required)

If the server uses OAuth, open the MCP panel inside a session:

/mcp

Select your server and choose Authenticate. Your browser opens to the provider's sign-in page. For servers that accept a static token, pass it with --header at add time instead.

4. Verify the connection

Check the server status:

claude mcp list

A ✔ Connected status means the server is ready. If you see ! Needs authentication, complete the OAuth flow from step 3. If you see ✘ Failed to connect, verify the URL with curl -I https://example.com/mcp.

5. Use the server

Start a session and ask Claude to use the connected tools. You can reference the server by name to be explicit:

Use the my-server tools to look up information from example.com
Tip: Claude Code automatically reconnects HTTP/SSE servers with exponential backoff. For OAuth servers, tokens are stored securely in your system keychain and refreshed automatically. Use claude mcp login <name> to run the OAuth flow from your shell without opening a session.
