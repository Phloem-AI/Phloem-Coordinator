Connecting Remote MCP in Gemini CLI

Gemini CLI can connect to remote MCP servers over Streamable HTTP or SSE. This guide covers adding a server, authenticating it, and testing the connection.

1. Gather your server details

Collect the MCP endpoint URL from your server provider. Most remote servers expose a single endpoint, for example https://example.com/mcp. Note whether the server requires a bearer token, API key, or OAuth access token.

2. Add the server with the CLI

Run this command from your terminal. Gemini CLI writes the server to the project configuration by default:

gemini mcp add --transport http my-server https://example.com/mcp

Use --scope user for a global server, or add --header "Authorization: Bearer YOUR_TOKEN" for a static bearer token.

You can also edit ~/.gemini/settings.json or a project-level .gemini/settings.json directly. Use httpUrl for Streamable HTTP and url for SSE:

{
  "mcpServers": {
    "my-server": {
            "httpUrl": "https://example.com/mcp",
      "headers": {
        "Authorization": "Bearer YOUR_TOKEN"
      }
    }
  }
}

For SSE, replace httpUrl with url and use the server's SSE endpoint. Keep real credentials out of the file by using environment-variable expansion in headers where appropriate.

3. Authenticate (if required)

For an OAuth-enabled server, omit static bearer headers. Gemini CLI can discover OAuth metadata after a 401 response. Use /mcp auth or /mcp auth my-server during an interactive session to start or manage authentication.

4. Restart and verify

Run gemini mcp list to inspect configured servers and connection status. Inside an interactive session, use /mcp to view discovered tools. If it shows as failed, verify the URL, transport, and token.

5. Test the connection

Start a new session and ask Gemini CLI to use the connected tools:

Use the my-server tools to look up information from example.com

If the connection works, Gemini CLI will ask for confirmation when required, invoke the tool, and return its result.

Tip: Gemini CLI supports includeTools and excludeTools in a server entry to control which tools are exposed. Its trust option bypasses tool-call confirmations, so enable it only for servers you fully control.
