Connecting Remote MCP in Codex (CLI & Desktop)

OpenAI Codex (CLI and Desktop) can connect to remote MCP servers. This guide covers adding an HTTP or SSE MCP server, authenticating it, and testing the connection.

1. Gather your server details

Collect the MCP endpoint URL from your server provider. Most remote servers expose a single endpoint, for example https://example.com/mcp. Note whether the server requires a bearer token, API key, or OAuth access token.

2. Add the server to your Codex configuration

In Codex CLI or the Desktop app, open the MCP settings and add a new server entry. The configuration uses the same structure as the OpenAI Responses API mcp tool type:

{
  "mcpServers": {
    "my-server": {
      "type": "http",
      "url": "https://example.com/mcp",
      "headers": {
        "Authorization": "Bearer YOUR_TOKEN"
      }
    }
  }
}

For OAuth-based servers, omit the headers field and authenticate through the app's MCP panel instead.

3. Authenticate (if required)

If the server uses OAuth, open the MCP panel in Codex and click Authenticate for your server. Complete the browser sign-in flow. For servers that accept a static token, pass it in the headers field at configuration time.

4. Restart and verify

Save the configuration and restart Codex CLI or reopen the Desktop app. The server should appear in your MCP server list with a connected status. If it shows as failed, verify the URL is reachable and the token is valid.

5. Test the connection

Start a new session and ask Codex to use the connected tools:

Use the my-server tools to look up information from example.com

If the connection works, Codex will invoke the tool and return results.

Tip: OpenAI's Responses API supports allowed_tools to restrict which tools from a server are exposed, and require_approval to control whether user approval is needed before each call. Set these in your server configuration to match your security requirements.
